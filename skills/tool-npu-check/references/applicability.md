# 适用范围与限制

运行 `npu-check` 前先确认本页条件。任一运行条件不满足时，不运行工具，并向用户说明不支持的具体条件。

## 运行条件

- 目标设备是 Ascend 950（dav-3510）。
- 使用与目标 NPU 和驱动匹配、且包含 `npu-check` 的 CANN 包。
- 目标程序是可执行文件，脱离 `npu-check` 后也能成功执行核函数。
- 应用通过 `<<<>>>` 完成单算子单次调用。
- 应用以单进程、单线程方式运行。

只有 Host 代码、文档或构建配置发生变化，没有能够复现目标路径的可执行 NPU 应用，或者任务只要求数值精度或
性能分析时，不运行 `npu-check`。

## 检查边界

- `memcheck` 仅检查受支持数据搬运指令的 GM 访问，不支持 scalar 单点访问检测。
- `synccheck` 检查核内 `SET_FLAG -> WAIT_FLAG`、`GET_BUF -> RLS_BUF` 配对及重复设置问题。
- `npu-check` 不替代数值精度、性能、Host 逻辑或构建验证。

## 同步指令硬件限制

- `SET_FLAG` 必须与对应的 `WAIT_FLAG` 成对使用，`GET_BUF` 必须与对应的 `RLS_BUF` 成对使用。
- 配对双方必须使用相同的 src/dst pipe、event ID 或 buffer ID 等 pair key，并执行相同次数。
- 分支、循环、尾块和提前返回等每条实际执行路径都必须完成配对，不能因路径低频或当前 shape 未卡死而只保留
  一端。
- 若确实不需要该同步关系，应同时移除配对双方；若存在数据依赖，则必须保留完整配对，不能以节省指令为由省略
  `WAIT_FLAG` 或 `RLS_BUF`。

## 结论边界

检查结论只覆盖本次命令、输入、实际执行路径、启用的检查类型和工具实际生成的报告。“本次未发现明确问题”不能
证明：

- 未执行的 shape、block 或条件分支没有问题；
- 未启用的检查类型没有问题；
- 本次未执行或工具未报告的其他 API、操作及访问没有问题；
- 超出本页运行条件的场景也受支持；
- 数值精度、性能、Host 逻辑或构建配置正确。

具体 API 或参数组合的覆盖范围不能由 API 名称或一次无报错结果推断。以当前 `npu-check --help`、CANN 官方
文档和实际报告为依据；资料未明确时标记为“覆盖未知”。
