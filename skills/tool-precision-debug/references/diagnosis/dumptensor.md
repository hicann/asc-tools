# DumpTensor 观察闭环

本章只讨论在 Ascend C Kernel 内主动调用 `AscendC::DumpTensor` 获取 Tensor 值，用于定位计算、搬运和数据依赖问题。**Runtime 自动采集模型或算子输入输出的 Dump 不在本章范围内。**

Kernel DumpTensor 生成的二进制调测数据使用 `show_kernel_debug_data` 解析。需要当前接口文档和示例代码时，使用 `/ascendc-docs-search` skill。

## 选择观察路线

| 当前需要 | 最短操作路线 |
| --- | --- |
| 先看中间值或异常分布 | 选择少量数据就绪点 → 加入 DumpTensor 并确认编译开关 → 重新构建、运行原输入 → 保存终端输出，按核与轮次对应到逻辑数据 |
| 保存原始数值并做精度比较 | 完成插桩和构建 → 由工程真实初始化入口加载 `dump_kernel_data=tensor` 配置 → 运行并采集到新目录 → 用配套 `show_kernel_debug_data` 解析 → 核对记录身份、dtype 与有效区，再按局部判据比较 |

已有可对应到输入和运行产物的 dump 时，直接从解析与比较继续。有限位数的终端文本适合观察趋势，不能用来恢复原始位模式；逐位比较需要保留二进制。配置格式与解析命令见[采集与直接解析](../../scripts/usage/kernel-debug-data-parse.md#采集与直接解析)。

## 准备

按[检查点设计](checkpoint-design.md#选择位置)选择能改变下一步判断的张量，记录源码位置、语义、dtype、shape、layout、有效区和可用参考。没有可靠局部判据时，可以先采集数值或检查适用的不变量，不自行套用最终输出的阈值判对错。局部参考与精度标准入口见[准备局部对照](checkpoint-design.md#准备局部对照)。

已有失败坐标时，反推实际 `core/row/tile/local offset`，按疑点选择首错位置、相邻正常区域或周期对照，方法见[错误分布与定位](localization.md)。采样范围由有效区和本轮问题决定，不固定只看核 0 或张量开头；尾块与后续循环的问题应观察对应轮次。

保留插桩前源码与原始失败依据，新建的源码快照、采集和解析文件放入[任务产物目录](reporting.md#任务产物目录)。复用工程已有采集方式即可；需要会话辅助时，再按[脚本用法](../../scripts/usage/dump-session.md)准备新鲜目录、源码快照和可选工具绑定。两种方式都保留本轮输入、实际产物与输出的关联。

## 最小插桩示例

下面示例依据 [9.0 接口](https://gitcode.com/cann/asc-devkit/blob/c8c1b9df6bb9cd61c09751c7ef414b89e06af274/docs/api/context/DumpTensor.md)和 [9.1 接口](https://gitcode.com/cann/asc-devkit/blob/e5451c7feba11f9e259f4fbc19c4bf82f8c0496c/docs/api/SIMD-API/基础API/调试接口/上板打印/DumpTensor.md)；当前产品、dtype、内存位置、地址限制和重载使用 `/ascendc-docs-search` skill 核对。

### 在已有 Kernel 中观察

以下片段要求 `srcLocal` 已分配且数据就绪，`dataLen` 是要观察的有效元素数：

```cpp
AscendC::DumpTensor(srcLocal, 101U, dataLen);
```

例如排查 `CopyIn → Compute → CopyOut`，可按疑点观察搬入后的输入、计算后写回前的结果，或写回完成后的对应 GM 数据。每个调用放到相应数据就绪的位置，不必三处都加；写回前后如何区分，见[根据结果继续定位](checkpoint-design.md#根据结果继续定位)。

| 参数 | 含义与关键条件 |
| --- | --- |
| `tensor` | 目标产品支持的 LocalTensor 或 GlobalTensor |
| `desc` | uint32_t 标签，用于对应语义位置；同一位置可以在不同核或轮次复用，配对方法见[对齐观察记录](#对齐观察记录) |
| `dumpSize` | 从传入 Tensor 起点观察的元素个数；不是字节数，不应超过可访问的有效范围 |
| `shapeInfo` | 展示形状，不执行转置或布局转换 |

上述 9.0.0、9.1.0 均提供 Local/Global 各带或不带 ShapeInfo 的重载。需要二维展示时，例如观察 16 个已就绪元素：

```cpp
uint32_t dims[] = {2U, 8U};
AscendC::ShapeInfo view(2, dims);
AscendC::DumpTensor(srcLocal, 102U, 16U, view);
```

按上述接口的展示规则，ShapeInfo 的元素数小于 dumpSize 时会截断展示，大于时缺少位置以 `-` 展示。例如 float32 的 `dumpSize=16`、shape 为 `2×4` 时，文本可只显示 8 个值，实际采集范围仍按 16 个元素确定。小 shape 不会缩小读取范围，也不能保护越界读取。

比较二进制前，用 dumpSize、dtype 和文件字节数核对有效数据；不同格式可能保留对齐填充，不能直接把整个文件都当有效元素。文本排版与 shape 展示也受配套解析器版本影响，显示不全不自动说明计算只写了这些元素。

### 编译、运行与打印条件

按工程原有命令重新构建，确认实际运行采用该产物；需要命令留证时可用[证据执行器](../../scripts/usage/run-with-evidence.md)。`ASCENDC_DUMP=0` 是编译宏控制，同名 shell 环境变量本身不会改变已有二进制；以实际构建采用的宏定义为准。无打印时按下方[观察异常时如何继续](#观察异常时如何继续)排查。

容量和硬件条件按目标环境查原文：9.0.0 的单次/每核总量说明与 9.1.0 的 SIMD FIFO 配置不同；后者给出 `simd_printf_fifo_size_per_core`。950 的 L1 支持还涉及 HDK 条件。默认值、产品缺项或旧限制未再出现，都不能直接推成所有版本的保证。

本页的 LocalTensor 示例属于 SIMD Tensor 打印；SIMT 字符串/标量打印读取其对应 printf 说明，不能直接照搬到 VF 中。

编译开关与上板配置可查[打印开关说明](https://gitcode.com/cann/asc-devkit/blob/e5451c7feba11f9e259f4fbc19c4bf82f8c0496c/docs/api/SIMD-API/基础API/调试接口/关闭ASCENDC_DUMP说明.md)、[NPU 调试指南](https://gitcode.com/cann/asc-devkit/blob/e5451c7feba11f9e259f4fbc19c4bf82f8c0496c/docs/guide/编程指南/调试调优/功能调试/NPU域上板调试.md)。

## 采集

1. 需要二进制时，在任务产物目录下选一个新的或空的 dump 子目录，按[配置与采集](../../scripts/usage/kernel-debug-data-parse.md#配置与采集)准备配置。这里的配置用于保存 Kernel 主动输出的调测数据，由工程真实的 ACL 初始化或框架入口加载；仅写出 JSON 文件不会启用采集。核对环境变量覆盖后的实际输出目录。
2. 使用已确认的原始失败命令运行插桩产物，保留原输入与运行输出。终端观察无需为了完成流程另配二进制采集。
3. 确认文件时间、输入、运行产物与本轮执行相符，而非陈旧结果。
4. 对 Kernel 调测数据优先使用当前 CANN 配套的 `show_kernel_debug_data`，保留原始文件，将解析结果写入新的解析子目录；需要路径隔离或异常产物整理时再用[解析适配器](../../scripts/usage/kernel-debug-data-parse.md)。

解析时同时查看退出码、异常文本和实际产物，不能仅凭返回 0 判断成功；具体版本差异见[判断解析是否成功](../../scripts/usage/kernel-debug-data-parse.md#判断解析是否成功)。文件生成或出现 tensor block 本身不证明采集完整，还需核对期望的核、观察点、轮次和有效数据是否齐全。

## 对齐观察记录

将记录对应到本次 Kernel 调用中的具体逻辑数据，再与参考配对。优先复用输出已有的标识，缺少必要信息时补少量逻辑标记，不要求另建固定格式的记录表。

- **desc 对应语义位置**：标签用于找到输入、计算结果等观察点；同一 desc 可以重复出现，不应假定后一次覆盖前一次，也不能用标签大小推断数据依赖顺序。
- **核标识对应执行归属**：终端 Block、解析文件 core 与 `GetBlockIdx()` 可能采用不同编号。先保留原始标识，通过已知分片、可辨识输入或少量逻辑编号输出建立对应；不要直接把文件 core 当成逻辑 block，也不要求把 blockIdx 一律编码进 desc。
- **记录次序对应源码轮次**：解析文件中的 `loop` 通常表示该核、该 desc 的记录次序，不自动等于 tileIdx。结合实际调用次数、循环与分支条件，以及 tile 或偏移标记核对；多次 Kernel 调用还需区分调用实例。

例如同一核同一 desc 的 `loop_0`、`loop_1` 只能先视为两次记录；若该点仅在部分 tile 执行，就不能据此把它们当成 tile 0、1。身份或有效区尚未对齐时，先保留未知，不能把配错的差异判为算子精度问题。

## 数据就绪与插桩影响

每个 dump 点先核对数据就绪关系：哪个 producer 已完成、哪一个 consumer 即将读取、张量的有效区和允许观察的时点。把“代码执行到此处”与“目标数据已就绪”分开；前者不能证明 DMA、异步流水或其他 core 的写入已经对该观察可见。就绪性未确认时，保留采集值作为瞬时状态，不能据此判定该阶段的计算结果正确或错误。

DumpTensor 的部分实现会在复制调测数据前后执行流水同步，如 `PIPE_ALL`，因此可能掩盖原来的同步缺陷；打印值正确不能证明未插桩程序的数据依赖正确。内部同步也不能替代跨核通信协议或正确的缓冲生命周期。DeQue 是队列流程中的一种就绪位置，TBuf 等流程应按自身依赖判断；不要为了打印统一添加 EnQue/DeQue 或额外的 `PIPE_ALL`。需要改变同步来验证候选时，将其作为单独的实验干预解释。

插桩可能改变资源占用、布局、编译优化或时序。需要区分插桩影响与环境漂移时，再采用 `Parent → dump probe → Parent` 对照：Parent 为未插桩版本，使用同一输入与原运行条件，中间只引入计划的 dump 变化；已有适用基线可复用。偶发问题按[复现性方法](reproducibility.md#判断稳定性)比较同条件下的失败率、位置和误差分布，一次 Parent 通过不抹去有效失败，也不能据此断定插桩改变了故障。

插桩改变原问题的关键时序、布局或观察条件时注明受扰动，不要求先取得两侧稳定失败。只要本轮比较仍有效，就保留其 PASS/FAIL 并限制对未插桩版本的推断；比较前提被破坏时才记为 `AMBIGUOUS`。边界变化另记 `BOUNDARY_CHANGED`，归因未明时保留待核实，不能用插桩后的通过覆盖原始失败。

## 观察异常时如何继续

| 现象 | 优先检查与下一步 |
| --- | --- |
| 没有预期打印 | 查实际产物、编译宏、调用分支和运行是否完成，再核对类型/位置支持、采样范围与容量；不要先假定 Kernel 未执行 |
| 有终端值但没有二进制 | 查配置是否经真实入口加载、是否选择 tensor、最终输出目录是否被环境变量覆盖；终端输出本身不证明落盘配置生效 |
| 有文件但解析报错、为空或缺少部分点 | 查工具与格式是否匹配、异常文本、路径限制及原始采集是否完整；保留已有文件，按配套说明处理，不将部分产物当成完整观察 |
| 值与参考不同 | 先核对核/轮次、dtype、layout、有效区、局部判据和数据就绪，再沿前后可比点检查计算与传递；全零、NaN、固定偏移等只提供候选，特殊值是否允许由算子与任务语义决定 |
| 插桩后原问题消失或边界变化 | 保留本轮有效结果，检查同步、资源与时序变化；按需做未插桩对照，不把插桩后的通过当成正式修复 |

同样的观察不再提供新信息时，换位置、参考或采集手段。只有满足[语义二分前提](semantic-bisection.md#前置条件)时才二分，不按固定尝试次数切换。怀疑旧构建时先核对实际加载的产物，按需清理明确属于当前工程的构建内容，不把清空全局缓存作为常规步骤。

## 比较与清理

按[检查点的比较前提与局部判据](checkpoint-design.md#准备局部对照)，将 NPU 观察与选定参考比较；已有项目比较器优先复用，需要辅助工具时见[精度比较器](../../scripts/usage/precision-compare.md)。按[结果状态](checkpoint-design.md#结果状态)登记 `PASS`、`FAIL`、`AMBIGUOUS` 或 `UNTESTED`，注明实际覆盖的切片与轮次。不可比较、解析异常和资源截断保留为限制；下一步沿可比观察定位具体代码或数据关系，不能仅凭某个 dump 异常认定根因。

取证结束后移除临时插桩，干净重建并按原入口回放，如实保留恢复后的比较结果；偶发问题本次未失败时注明，不要求为完成清理反复重跑到失败。使用会话工具时按其 close 用法关联恢复证据；手动采集同样确认源码恢复与干净回放。恢复确认说明临时改动已清理，不表示精度已修复。
